Reading this site

Request string
/directory/table:run:variation:date names one set of constants. The Request page builds it from its parts; every assignment page shows the exact string that identifies its data, with the date of its creation.
Variations
A request for a variation that has no assignment for the table and run falls back to the variation it inherits from, down to default. See Variations.
Compare variations
The eye of a variation, or Compare variations, lists the tables that take their constants from that variation instead of the ones it inherits from: every table with an assignment between the chosen parent and the variation. A run or a time narrows the assignments considered.
Compare assignments
Compare, the Compare button of a table and the buttons of an assignment page put two sets of constants of one table side by side: name each side by its request string or its database id, or build it from the parts. On a table's page, Pick to compare shows a checkbox per assignment: the first two picked are A and B, a third pick drops the oldest, and the picks stay while you page or search the list. Changed cells are tinted green; a changed number shows its difference on hover. Per cell stacks the B value over the A value, Per column puts them side by side, Table to table shows the two tables one above the other. Changed rows hides the rows without a change (the default above 20 000 cells), and the rows come in pages of 200. Unified diff downloads the whole comparison as a .diff file in the format of diff -u and git diff, which every diff viewer opens: one line per row in the layout of the text download, the two header lines naming A and B by request string, three rows of context around a change; a hunk's line number is the row index of the page plus one. The same comparison is served as JSON at /compare/data.json?a=…&b=… and as the diff at /compare/data.diff.
Finding a table
The filter box of Tables matches text anywhere in a path. With * (any text) or ? (one character) the pattern must match a whole name, or a whole path when it contains /, as in ccdb ls. Sort A…Z and Sort by ID order the tree by name or by database id, the order things were created in; the choice stays, like the open directories. The info button of a table, and Show info on the table's own page, tell how many assignments it has and when the last one was added.
Data layout
On an assignment page and on the compare page, Vertical shows the data with one line per row and Horizontal with one line per column, the shape you see on a table with many rows. Auto picks Horizontal for a one-row table with more than two columns, the usual parameter table, and Vertical otherwise. ccdb cat uses the two words the other way round.
Logs
The Logs list truncates long comments. A click on a row, or on its Created stamp, opens the record with the full comment and the objects it affected, linked to their pages while they exist: the assignment, the table, the directory or the variation.
Data downloads
The data table of an assignment comes in pages of 200 rows, every row with its index from 0. The downloads hold everything: the data as text in the ccdb dump layout and as JSON (columns and rows as strings).
